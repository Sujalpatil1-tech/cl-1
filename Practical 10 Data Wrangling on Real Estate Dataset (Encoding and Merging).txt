# Step 1: Import required libraries
import pandas as pd
import numpy as np

# Step 2: Create Property Dataset
property_data = {
    'Property_ID': [101, 102, 103, 104, 105],
    'Owner_ID': [1, 2, 3, 1, 2],
    'City': ['Nashik', 'Pune', 'Mumbai', 'Pune', 'Nashik'],
    'Property_Type': ['Flat', 'House', 'Flat', 'Plot', 'House'],
    'Price': [4500000, 6500000, 8000000, 3000000, 5500000]
}

property_df = pd.DataFrame(property_data)

# Step 3: Create Owner Dataset
owner_data = {
    'Owner_ID': [1, 2, 3],
    'Owner_Name': ['Amit', 'Rahul', 'Priya'],

print("Property Dataset:")
print(property_df)

print("\nOwner Dataset:")

## **1. Aim**

To perform data wrangling on a Real Estate dataset using encoding and merging techniques to convert raw data into a clean, structured, and analysis-ready format.

## **2. Theory**

### **A. Data Wrangling**

Data Wrangling, also known as Data Munging, is the process of collecting, cleaning, transforming, and organizing raw data into a suitable format for analysis and machine learning.

Real estate datasets contain information about properties, such as:

- Property ID
- Property location
- Property type
- Number of bedrooms
- Area of property
- Property price
- Furnishing status
- Number of bathrooms

**Example:** A real estate company may maintain property details in one dataset and location details in another dataset. Data wrangling helps clean and combine these datasets for property price analysis.

### **B. Encoding**

Encoding is the process of converting categorical data into numerical form so that machine learning algorithms can process it.

Categorical data contains text values such as Apartment, Villa, Pune, Nashik, Furnished, and Unfurnished.

There are two commonly used encoding techniques:

**1. Label Encoding**

Label Encoding assigns a unique numerical value to each category.

Example:

| Property Type | Encoded Value |
| ------------- | ------------- |
| Apartment     | 0             |
| Villa         | 1             |
| Plot          | 2             |

- Each category is represented by a numerical label.
- It is useful when categories have a meaningful order or when an algorithm can handle arbitrary category codes.
- For nominal categories, arbitrary numbers may incorrectly suggest an order.

**2. One-Hot Encoding**

One-Hot Encoding creates separate binary columns for each category.

Example:

| Property Type | Apartment | Villa | Plot |
| ------------- | --------- | ----- | ---- |
| Apartment     | 1         | 0     | 0    |
| Villa         | 0         | 1     | 0    |
| Plot          | 0         | 0     | 1    |

- Each category gets a separate column.
- Value 1 represents the presence of a category.
- Value 0 represents its absence.
- It avoids assigning an artificial numerical order to categories.

### **C. Merging**

Merging is the process of combining two or more datasets using a common column or key.

For example:

**Dataset 1: Property Details**

| Property ID | Property Type | Price   |
| ----------- | ------------- | ------- |
| 101         | Apartment     | 4500000 |
| 102         | Villa         | 8000000 |
| 103         | Plot          | 3000000 |

**Dataset 2: Location Details**

| Property ID | Location |
| ----------- | -------- |
| 101         | Nashik   |
| 102         | Pune     |
| 103         | Mumbai   |

After merging:

| Property ID | Property Type | Price   | Location |
| ----------- | ------------- | ------- | -------- |
| 101         | Apartment     | 4500000 | Nashik   |
| 102         | Villa         | 8000000 | Pune     |
| 103         | Plot          | 3000000 | Mumbai   |

Here, `Property ID` is the common key used to combine both datasets.

### **Types of Merging**

| Join Type  | Description                                                                            |
| ---------- | -------------------------------------------------------------------------------------- |
| Inner Join | Returns only matching records from both datasets.                                      |
| Left Join  | Returns all records from the left dataset and matching records from the right dataset. |
| Right Join | Returns all records from the right dataset and matching records from the left dataset. |
| Outer Join | Returns all records from both datasets, including unmatched records.                   |

## **Step 4: Merge both datasets**

```
merged_df = pd.merge(    property_df,    owner_df,    on='Owner_ID',    how='inner')
```

- `pd.merge()` combines two DataFrames into a single DataFrame.
- `property_df` is the first dataset.
- `owner_df` is the second dataset.
- `on='Owner_ID'` specifies the common column used to combine both datasets.
- `how='inner'` performs an Inner Join.
- `merged_df` stores the combined dataset.

**What is Inner Join?**

Inner Join returns only those records where the common column exists in both datasets.

For example:

- Owner ID 1 belongs to Amit.
- Owner ID 2 belongs to Rahul.
- Owner ID 3 belongs to Priya.

Their names and contact numbers are added to their respective property records.


## **Step 5: Apply One-Hot Encoding**

```
encoded_df = pd.get_dummies(    merged_df,    columns=['City', 'Property_Type'],    dtype=int)
```

- `pd.get_dummies()` performs One-Hot Encoding.
- `merged_df` is the input DataFrame.
- `columns=['City', 'Property_Type']` specifies the categorical columns to encode.
- `dtype=int` creates integer values (0 and 1) instead of Boolean values.
- `encoded_df` stores the encoded dataset.

**What is One-Hot Encoding?**

One-Hot Encoding converts categorical values into separate numerical columns containing 0 and 1.

For example, the City column contains:

| City   |
| ------ |
| Nashik |
| Pune   |
| Mumbai |

After encoding:

| City_Nashik | City_Pune | City_Mumbai |
| ----------- | --------- | ----------- |
| 1           | 0         | 0           |
| 0           | 1         | 0           |
| 0           | 0         | 1           |

Similarly, the `Property_Type` column creates:

- `Property_Type_Flat`
- `Property_Type_House`
- `Property_Type_Plot`

Here:

- `1` means the category is present.
- `0` means the category is absent.
